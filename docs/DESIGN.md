# Steward’s visual and interaction language

## Implemented design

Porcelain surfaces, ink typography and restrained cobalt replace the green/black palette. The calm state centers a single zero; small rows establish the synthetic world without dashboard panels. One primary interaction starts the story. Color indicates decisions and evidence, not an ambient AI aesthetic.

The impact graph remains spatial, followed by three futures and one decision. After approval, parallel lanes expose observable work. The counteroffer compares nominal value with personal value; verification ends the story. The final tally derives its milestone count from actual events rather than inventing an action total.

Repeated backend events update the current scene without restarting its entrance animation, reducing flicker and disappearing content. Transitions communicate a change of state. Reduced-motion users receive near-instant transitions. Drawers trap keyboard focus, support Escape, restore the trigger, and make the background inert. Primary and footer controls use practical touch targets.

## Reference interpretation

These are product interpretations of the supplied fictional references, not visual copies or claims of implementation:

| Reference | Steward principle |
| --- | --- |
| JARVIS / FRIDAY | competence is visible in proactive actions and coordinated consequences |
| Samantha | calm interface, continuity, very little interaction when nothing needs judgment |
| The Machine | persistent world model, event detection, explicit boundaries and values |
| Star Trek computer | one intelligence available across surfaces |
| KITT | current context matters more than a generic task prompt |
| TARS | understandable behavior, explicit human authority and stop |
| Minority Report | spatial consequences become a compact decision |
| HAL / Samaritan / Rehoboam / Black Mirror | reject opaque control, unchecked surveillance and self-granted authority |

Modern OS guidance informs usability, not branding. [Apple’s motion guidance](https://developer.apple.com/design/human-interface-guidelines/motion) treats motion as feedback and status; [Apple’s accessibility testing guidance](https://developer.apple.com/documentation/accessibility/testing-system-accessibility-features-in-your-app) motivates reduced-motion verification. [Playwright’s accessibility testing documentation](https://playwright.dev/docs/accessibility-testing) supplies the axe integration. Automated scans catch common violations but cannot establish complete accessibility compliance.

## Best UI assessment

The strongest differentiator is the choreography of outcome ownership: calm → impact graph → compressed futures → one decision → independent execution → defense → verification → calm. The revised identity is cleaner and more legible on phones. The interface is custom because chat primitives would obscure this sequence; assistant-ui is not integrated. Award competitiveness is a design judgment, not a verified result.
